## 版本亮点

### 🤖 Grok 与 Grok Build 原生接入

- 新增 Grok OAuth 账号、xAI API Key 和 xAI-compatible 中转来源，支持导入 Sub2API Grok JSON、加密保存凭据及原子持久化刷新令牌轮换。
- 新增独立 Grok 号池协议，Grok 与 OpenAI 账号不再混入同一普通号池或聚合中转；导入的 Grok 账号自动获得 `Grok` Tag。
- Grok Build 使用独立端点、本地令牌、模型目录和 TOML 配置，仅接受原生 Responses Grok 号池或 Grok 中转，不再经过 OpenAI Responses 二次转换。
- 完善 Codex ↔ Grok 工具桥，支持自定义工具声明、`tool_choice`、工具调用与结果回传，修复工具被当作普通 JSON 文本及未声明工具导致的 422。

### 🔀 Claude / Anthropic 协议与模型适配

- 完善 OpenAI Responses 与 Anthropic Messages 双向转换，覆盖系统提示、文本/图片、严格函数工具、工具结果、停止原因、流式事件与 Token 用量。
- 根据 Claude 型号适配 adaptive thinking、旧版 thinking budget 和 reasoning effort，不向客户端泄露隐藏思考内容。
- Codex 可通过路由模型映射使用 Claude 上游；Claude Code 也可连接兼容的 Stone+ 来源。
- 一键连接与重启修复会清理 Claude 配置中残留的 GPT/xAI 模型覆盖，避免 Claude Code 因错误模型名称拒绝访问。

### 🧩 客户端管理与会话修复

- 重构顶部 Agent 控制器，统一管理 Codex Desktop、Codex CLI、Claude Code、Gemini CLI 与 Grok Build；运行时显示“关闭/重启”，停止时只显示“开启”。
- 重启改为完整事务：关闭客户端、备份并修复配置，Codex 还会修复会话与工作区索引，最后重新启动并确认进程真正存活。
- 加强 Windows 终端及子进程树关闭、PID 复用防护、启动就绪检测、失败回滚和应用重启后的托管进程恢复，不误杀外部终端中的用户会话。
- 会话修复改为有界扫描与事务计划，支持进度、取消、并发限制、过期预览拒绝及失败回滚；Codex Micro 禁用启动失败时会安全回退正常启动。

### 🌐 代理、性能与窗口可靠性

- 修复 Windows 选择“系统代理”并显示已接管后，WinINet 实际未写入 mixed 地址的问题；写入后必须回读确认才会发布 ready。
- 强化系统代理、TUN 与 LAN 独立状态、原子切换和失败回滚；核心或临时 TUN 异常时继续 fail-closed，避免直连泄漏及系统遗留失效代理。
- 节点/分组可折叠，当前选择和工作台页签会跨重启恢复；延迟测试增加 ready、并发和超时边界，避免把排队时间误算为节点延迟。
- 高并发期间合并和限频运行时增量，请求记录使用分页与有界渲染，降低 Stone+ 窗口聚焦时的 Windows 桌面卡顿。
- 修复主内容区与原生 titlebar 之间的阴影断裂、模糊层溢出与窗口按钮区裁切。

### 📊 计价、安全与发布供应链

- 新增 Grok 4.5 与 Claude Fable、Mythos、Opus、Sonnet、Haiku 系列的标准 API 等价计价，区分长上下文、5 分钟/1 小时缓存写入和缓存读取。
- 成本统计优先使用路由映射后的实际上游模型；历史账本只迁移能够证明 Token 口径的日志，无法确认的旧记录继续显示“未计价”。
- 强化 Grok OAuth 上游白名单、IPC 来源校验、模型映射防污染和 Windows 自动更新证书指纹校验；GitHub Actions 外部依赖继续固定到完整 Commit SHA。
- 本版本继续使用 [StonePlus Source Available License 1.0](https://github.com/M4rkzzz/stone-plus/blob/v0.9.8/LICENSE)；安装程序会展示并要求同意许可证。完整的源码获取与品牌边界见 [SOURCE_ACCESS.md](https://github.com/M4rkzzz/stone-plus/blob/v0.9.8/SOURCE_ACCESS.md) 与 [TRADEMARKS.md](https://github.com/M4rkzzz/stone-plus/blob/v0.9.8/TRADEMARKS.md)。
