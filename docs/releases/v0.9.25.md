# Stone+ v0.9.25

## 版本亮点

### 🎯 中转站使用实际请求模型

- 修复旧版一键连接 Codex 中转站留下的默认模型限制和通配映射：例如请求 `gpt-6.1-sol` 时，符合迁移条件的旧来源不会再静默转发为 `gpt-5.6-sol`。
- 自动检查原修复前创建、同协议直连、已公开多个模型且仍保留单模型默认值的历史配置，无需用户重新添加中转站。

### 🔁 历史配置只检查一次

- 为旧 Codex 路由记录一次性检查标记，避免每次启动重复迁移。
- 检查完成后，用户主动重新设置的模型限制和映射会继续保留，重启不会再次清除。

### 🛡️ 保留其他路由策略

- 新建来源、号池、跨协议映射、精确模型别名以及按模型选源配置维持原行为。
- 迁移只调整匹配的账号模型开放策略与路由默认映射，不修改来源地址、凭据或客户端安装配置。

## 验证

- AppStore 的 126 项测试通过，覆盖历史配置迁移、重启持久化和迁移后显式重新设置。
- Node.js 22.20.0 / npm 10.9.3 下，ESLint、TypeScript、224 个测试文件、2988 项测试与生产构建通过，2 项按平台跳过。
- 五个平台 sing-box 固定摘要与 Windows frpc 校验通过；Windows 安装包、便携包和主程序的持续签名指纹与时间戳校验通过，随包代理核心启动与退出烟测通过。
- 本机 Electron 烟测在进入应用代码前原生退出；签名 EXE、隔离烟测复制件和开发 Electron 均出现该启动问题，Windows 打包态应用烟测仍须通过发布工作流的阻断验收。

## 下载

- Windows x64 推荐 `StonePlus-0.9.25-windows-x64-setup.exe`；免安装使用 `StonePlus-0.9.25-windows-x64-portable.exe`。
- macOS 提供 Intel / Apple Silicon 的 dmg 与 zip；Linux 提供 x64 / arm64 的 AppImage 与 deb。
- `StonePlus-0.9.25-source.tar.gz` 为本版本完整源码，另附 sing-box 1.13.14 对应源码归档。
- 使用 `SHA256SUMS`、GitHub Artifact Attestation 和 `StonePlus-CodeSigning.cer` 核对完整性与来源。

> [!WARNING]
> 旧版配置没有记录默认映射的来源，因此与自动默认值完全同形的历史显式限制，也会在首次检查时迁移；检查后重新设置的限制会保留。
>
> Windows 使用项目持续自签名 Authenticode 证书，仍可能出现 SmartScreen 提示；macOS 使用 ad-hoc 签名且未经 Apple 公证。Linux 凭据存储依赖可用的系统密钥环。
