# Stone+ v0.9.17

## 版本亮点

### OAuth 与 Codex App 切换不再丢账号

- ChatGPT 和 Grok OAuth 刷新统一进入账号级单飞门：并发请求只允许一次令牌轮换，后到请求复用新凭据，避免旧 refresh token 被二次使用后撤销。
- 上游 401 会在确认账号身份完全一致后重建全部认证与工作区请求头，并仅重放 Stone+ 已在内存中验证过的 JSON；不会跨账号恢复，也不会重放已经开始输出的流。
- Codex App 官方账号入口新增认证所有权、最终轮换 token 和失败回滚校验；用户重新执行“一键连接”时，会先回收仍由 Stone+ 管理的官方 OAuth 残留，再恢复本地网关配置。

### 会话修复更快、更省硬盘且可恢复

- 客户端启动改用轻量 `startup-index` 修复，只同步 SQLite 运行索引和模型缓存，不再每次重写完整历史；手动完整修复仍覆盖 JSONL、工作区状态和数据库索引。
- 大型会话优先使用同文件系统硬链接快照或等长补丁日志，只有确实需要改变文件长度时才原子生成新文件；操作前检查磁盘空间，失败后自动回滚并清理临时备份。
- 修复过程提供发现、扫描、校验、备份和应用进度，并可安全取消。取消或并发变化不会覆盖 Codex 刚写入的新内容。
- Stone+ 现在与 Codex 一致识别 `CODEX_HOME`、配置中的 `sqlite_home` 和 `CODEX_SQLITE_HOME`；外置 `state_5.sqlite` 的标题读取、会话删除、恢复、修复和安全备份使用同一物理路径。

### 压缩请求和长上下文更稳

- 本地 Responses 网关接受 gzip、Brotli、deflate、Zstandard 以及按标准顺序叠加的压缩 JSON 请求，兼容新版 Codex 和第三方客户端的请求压缩。
- 压缩体与展开体都受严格大小限制；压缩请求在展开前预留共享大请求预算，阻止多个小型压缩炸弹同时占满内存。
- 未知编码、超过四层编码、损坏压缩流和超过 64 MiB 的展开内容分别返回明确的 415、400 或 413，不把半截请求送给上游。

### DeepSeek、Grok 与调度恢复更可靠

- DeepSeek/Grok 桥继续完整暴露当前 Codex 请求声明的工具，保持自定义参数、并行批次、调用 ID、结构化结果和停止原因；未声明或损坏的调用仍然 fail-closed。
- 模型不支持或短期容量不足不再把整个 OAuth 账号错误冷却：Stone+ 分离账号健康、账号/模型冷却和请求级过载，并在安全范围内优先同账号短延迟重试。
- Grok 增加有界图片/视频代理、稳定会话绑定和 OAuth 轮换恢复；媒体响应、日志与诊断均有限额且不持久化 token、工具参数或原始媒体帧。
- 持久化诊断会对 Bearer、API Key、URL 查询凭据和嵌套错误数据统一脱敏，远端问题可定位但不会把完整凭据写入日志。

- 官方维护者身份、规范仓库、许可证 SHA-256、Windows 证书指纹、GitHub 权限和编辑门验证通过。
- ESLint、TypeScript、Electron 生产构建及完整测试通过；214 个测试文件，2747 项通过，1 项按平台条件跳过。
- 新增压缩请求、OAuth 轮换、同账号 401 恢复、外置 Codex SQLite、低写入会话修复、DeepSeek/Grok 工具与媒体边界的专项回归。
- 开发与生产依赖审计均为 0 漏洞；frpc 0.69.0 与 sing-box 1.13.14 的全部发布运行目录及 SHA-256 清单验证通过。

- Windows x64 推荐下载 `StonePlus-0.9.17-windows-x64-setup.exe`；免安装使用 `StonePlus-0.9.17-windows-x64-portable.exe`。
- macOS 提供 Intel 和 Apple Silicon 的 `.dmg` 与 `.zip`；Linux 提供 x64/arm64 的 AppImage 和 deb。
- `StonePlus-0.9.17-source.tar.gz` 是签名标签对应的完整 StonePlus 源码；同时提供 sing-box 1.13.14 对应源码材料。
- 使用 `SHA256SUMS`、GitHub Artifact Attestation provenance 和 `StonePlus-CodeSigning.cer` 交叉验证下载来源与完整性。
