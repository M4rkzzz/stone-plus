# Stone+ v0.9.18

## 版本亮点

### 🐋 DeepSeek Harness 成为完整客户端

- 新增 DeepSeek Harness 一键安装、配置、启动、停止与重新聚焦，支持 GPT 官方账号、OpenAI Responses 中转和原生 DeepSeek 来源，不要求用户维护 Stone+ 专用服务器。
- Stone+ 会把真实模型目录、上下文窗口、最大输出及推理档同步到 Harness；新会话可选择 GPT-5.6 或 DeepSeek，第一次真实生成后锁定模型家族，后续只展示同族模型。
- DSH 客户端的原生链路固定为 OpenAI Responses：模型、搜索、工具、并行调用、调用 ID、结构化结果和停止原因全部经过独立网关命名空间，避免与 Codex、Grok 或普通 OpenAI Chat 路由串线；旧版 Chat Completions 仅作为兼容别名保留。

### 🔄 Codex 会话可选择性原生迁入

- 迁入弹窗只扫描 Codex 会话摘要，避免为展示列表读取和哈希全部历史；用户可按标题、项目或会话 ID 搜索并最多选择 50 条。
- 会话会转换为 DeepSeek Harness 原生事件格式，保留用户/助手文本、推理、工具调用及结果的 ID、顺序和错误状态，同时自动创建并绑定原项目工作区。
- 导入以来源修订和本地收据保证幂等：重复迁入显示“已存在”，来源变更后可生成新修订；迁入成功只提示结果，不自动打开客户端。

### 🧠 长上下文、压缩与工具链更稳

- DeepSeek Harness 的原生 Responses 与兼容 Chat 历史统一支持受控的 10–64 MiB 大请求通道；共享字节门控继续限制并发内存，超过硬上限稳定返回 413。
- 健康 Responses 流的终态等待放宽到 65 秒；输出前遇到非 JSON、空响应、错误 Content-Type、提前断流或短期过载时进行小次数自适应重试，连续失败后再明确报告。
- 开始向客户端输出后仍不跨账号或中转续写；未声明、损坏或无法保持语义的工具调用继续 fail-closed，避免假成功和静默误操作。

### 📊 额度、路由与客户端维护增强

- Codex 额度页新增月度窗口、订阅方案、模型专属额度桶、重置券操作，以及额度达到 100% 后仍成功使用的“Stone+ 已释放隐藏额度”美元估算。
- 额度状态按真实重置边界和新鲜度恢复，模型专属额度耗尽不再误伤整账号；定价目录同步补齐 GPT-5.6、DeepSeek 及相关模型。
- 号池新增受控 WM 路由，路由预览、实际调度和计价使用一致的上游模型；一键连接与重启修复继续清理第三方 Codex 配置残留，并加固客户端安装检测和进程生命周期。
- 内置代理启动额外识别 IPv4-mapped IPv6 回环、SOCKS4 规则，并在启动 sing-box 前统一验证 Chromium Fetch 可用端口，降低远端系统代理策略导致的假启动。
