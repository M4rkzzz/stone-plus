## 版本亮点

### 🧩 Kiro Claude 专用中转与完整工具链

- 新增独立 `Kiro Claude` 协议；Claude Code CLI、Claude Code Desktop 与 Claude Code VSC 保持标准 Anthropic Messages 入站，Stone+ 直接转换为 Kiro 原生 conversation state 与 AWS Event Stream，再输出 Anthropic SSE。
- 完整保持历史及并行 `tool_use` / `tool_result` 的 ID、顺序和批次关系，补齐工具增量、reasoning、usage 与 `stop_reason`；不再把有效工具结果降级为 `Continue` 或占位文本。
- Kiro 来源只对三个 Claude Code 表面可见，必须通过真实两轮工具烟测后才能绑定或进入聚合；会话粘滞、输出前故障切换和输出后禁止跨源续写均采用 fail-closed 边界。

### 🖥️ Claude 客户端管理与配置修复

- 新增 Claude Code Desktop 与 VS Code 扩展的检测、配置和启动入口，并保留 Claude Code CLI；Desktop 支持恢复官方模式，VSC 使用扩展宿主配置，不把不同表面的进程和配置混为一体。
- 客户端启动、关闭和重启改为身份感知事务：先确认真实进程状态，再备份和修复配置；具备会话修复能力的表面会按“关闭 → 修复 → 开启”执行，失败时保留可恢复状态。
- Claude 配置默认关闭归因头，非必要流量保持高级可选；清理 GPT/xAI 模型残留，并在权限模式从 Manual 切换到 Auto 时提示新建会话，不自动重放旧的待确认调用。

### 🌗 深色模式、窗口与大列表性能

- 新增跟随系统、浅色和深色主题，统一原生 titlebar、窗口按钮、主内容区阴影与各工作台色彩；主题跨重启持久化，并在主进程与 renderer 间同步。
- 账号主表和导出列表采用分页与 Map/Set 聚合，OAuth 秒级倒计时隔离渲染；客户端、FRP、请求记录及运行时状态使用事件优先、可见性暂停、单飞与自适应轮询。
- 精简客户端后台任务和控件间距，减少无意义全页重绘，缓解高并发且 Stone+ 窗口聚焦时的 Windows 桌面卡顿。

### ⚙️ Gateway、路由与数据可靠性

- 完善 Kiro、Grok、Anthropic 与 OpenAI 的工具流、流式终态、WebSocket 背压和非流式聚合；缓冲响应在尚未提交客户端时可安全切换来源，输出开始后禁止跨源拼接。
- 号池、聚合中转、路由、Renderer、IPC 与 Store 共享同一来源资格和协议拓扑校验；拒绝跨协议成员、重复 ID、未验证 Kiro 来源及通过旧 IPC 篡改 OAuth 系统来源。
- SQLite 加入敏感页物理清除、带摘要的数据库替换 journal 和启动恢复；凭据导入使用持久回滚，浏览器 JSON 缓存通过 safeStorage 加密，Grok 刷新令牌轮换采用凭据级 singleflight。

### 🛡️ 代理、运行时与发布供应链加固

- 修复 sing-box/TUN 启停、系统代理租约、Chromium reload 与崩溃恢复边界；Windows ACL、PowerShell 参数传递、进程身份和自签名宿主校验均保持严格 fail-closed。
- frpc 0.69.0 使用固定归档及运行文件 SHA-256 清单，sing-box 1.13.14 五个平台运行目录继续逐文件校验；Electron 启用 ASAR 完整性及禁用 RunAsNode、NODE_OPTIONS 与 inspect 的 fuses。
- 固定 Node.js 22.20.0 与 npm 10.9.3 工具链，升级 PostCSS 至已修复版本，封堵路径穿越读取 `.map` 文件的开发期依赖告警。
- 本版本继续使用 [StonePlus Source Available License 1.0](https://github.com/M4rkzzz/stone-plus/blob/v0.9.9/LICENSE)；源码公开不代表允许修改、衍生或再分发，完整边界见 [SOURCE_ACCESS.md](https://github.com/M4rkzzz/stone-plus/blob/v0.9.9/SOURCE_ACCESS.md) 与 [TRADEMARKS.md](https://github.com/M4rkzzz/stone-plus/blob/v0.9.9/TRADEMARKS.md)。
