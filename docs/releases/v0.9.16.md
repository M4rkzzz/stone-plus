## 版本亮点

### 🧰 DeepSeek Codex 工具链完整可用

- DeepSeek V4 现在同时支持原生 Responses DSML 和 DeepSeek-compatible Chat Completions 两条工具通路，Codex 不再只能对话而无法编辑文件或跨任务通信。
- 完整恢复函数工具、自定义工具、`tool_search`、命名空间与动态工具结果，保持调用 ID、结构化参数、历史顺序和并行工具批次；跨任务消息等能力只要由当前 Codex 请求声明即可正常调用。
- 流式桥接会把 DSML 或 Chat 工具结果还原为标准 Responses 事件；未声明工具、坏参数、截断 DSML、原生/DSML 混用或终态缺失均明确报错，不把工具文本伪装成成功回答。

### 🧠 DeepSeek V4 推理与长上下文适配

- DeepSeek 来源默认使用最高 `max` 推理档，并可在来源编辑页选择 `none`、`low`、`high` 或 `max`；旧配置无损迁移到最高档。
- 为 `deepseek-v4-flash` 补齐 1,048,576 Token 上下文、384,000 Token 最大输出和 Codex 专属模型能力目录，包含自由格式补丁、Shell、工具搜索、并行调用和多代理能力声明。
- 只有 Codex 路由中的全部启用来源均为 DeepSeek 时才写入 1M 全局上下文，按模型分流到 GPT、Claude 或其他来源时不会错误继承 DeepSeek 限制。
- 健康流终态空闲等待由 30 秒放宽至 65 秒，并识别 DeepSeek 推理进度，长推理不再被误判为无终态。

### 🔄 中转协议与配置恢复更稳

- DeepSeek-compatible 中转可明确选择 OpenAI Responses 或 Chat Completions；保存、探测、模型目录、重启恢复和网关调度统一遵循所选协议。
- Codex 客户端管理扩展到 `config.toml`、认证文件、生成模型目录、全局 `AGENTS.md` 与默认规则文件，模型目录由 Stone+ 生成并只读展示，个人指令和规则仍可在高级编辑器中维护。
- “重启修复”现在同步处理第三方切换器遗留的模型名：在安全备份后修复会话 JSONL、SQLite 的 Provider/模型索引及工作区状态，再校验配置并启动 Codex。
- 修复页面显示配置正常、顶部 Agent 控制却提示“尚未接入”而无法启动的状态分裂；即使 renderer 持有旧快照，主进程仍会执行原子修复、验证和启动。

### 💵 计价与诊断更准确

- 增加 DeepSeek V4 Flash 与 V4 Pro 的输入、缓存读取、缓存写入和输出计价，支持普通模型名、`[1m]` 变体与 `deepseek/` 命名空间。
- 额度周期分别记录 5 小时和 7 天范围内的未定价 Token，未知模型不再被静默当作零成本；界面会明确提示未计价数量。
- DeepSeek 工具桥新增工具数量、调用数量、停止原因及错误分类回归，方便区分来源不兼容、模型输出损坏和客户端配置残留。
